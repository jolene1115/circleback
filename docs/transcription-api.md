# Transcription API: What Was Built

Part of **PitchPerfect**, the AI public speaking and interview coach.
This piece turns a speech recording into a **verbatim transcript**, keeping filler words like "um", "uh" and "like", using the free Gemini API. Later features (pace, filler-word metrics, AI feedback) build on this output.

Status: **working and tested** (CLI and HTTP endpoint). Not committed or pushed yet; everything is still on `main` as local changes.

---

## Files added

| File | What it does |
|---|---|
| `package.json` | Project config, dependencies, and the `server` / `start` / `transcribe` scripts |
| `.env.example` | Template for your settings (key left blank). Copy it to `.env` |
| `.gitignore` | Keeps `.env`, `node_modules/` and test recordings out of git |
| `server/transcribe.js` | Sends the audio to Gemini and returns `{ transcript, fillerWords, wordCount }`. Retries automatically when Gemini is busy (503) |
| `server/index.js` | Express server: `GET /api/health` and `POST /api/transcribe` |
| `server/transcribe-cli.js` | Test from the terminal without starting the server |
| `server/requests.http` | Ready-made requests for VS Code/Cursor's REST Client extension |
| `samples/` | Put test recordings here (git-ignored) |
| `README.md` | Setup and usage instructions |

Dependencies: `express`, `multer` (file uploads), `dotenv` (reads `.env`), `@google/genai` (official Gemini SDK).

## Setup (for each teammate)

1. Install Node.js 20+ (`brew install node`).
2. Get a free key at <https://aistudio.google.com/app/apikey>.
3. Run `cp .env.example .env`, then paste your key after `GEMINI_API_KEY=`.
4. Run `npm install`.
5. If you get a 403 "Gemini API has not been used in project…" error, open the link in the error message and enable the Gemini API for your Google project, then wait a minute or two.

> Never commit `.env` or paste your key in chat. Git ignores `.env`, so it won't appear in the Changes panel. That's expected.

## How to test (no frontend needed)

```bash
# Quickest: calls Gemini directly
npm run transcribe -- samples/your-recording.m4a

# Or through the API
npm run server
curl localhost:3001/api/health
curl -F "audio=@samples/your-recording.m4a" localhost:3001/api/transcribe
```

Supported formats: webm (browser recording), mp3, wav, m4a/mp4 (iPhone voice memo), aac, ogg, flac. Max 20MB.

## API

### `POST /api/transcribe`
Multipart form with a field named `audio`.

```json
{
  "transcript": "Um, so, like, I worked on a project last summer where, uh, we built a website...",
  "fillerWords": [{ "word": "um", "count": 1 }, { "word": "uh", "count": 1 }],
  "wordCount": 32,
  "model": "gemini-3.8-flash",
  "ms": 13684
}
```

| Status | Meaning |
|---|---|
| 400 | No file, or not a supported audio type |
| 413 | File over 20MB |
| 429 | Free-tier rate limit; wait a minute |
| 500 | Key missing from `.env`, or another error |
| 503 | Gemini overloaded (already retried 3 times) |

### `GET /api/health`
`{ "ok": true, "keyConfigured": true, "model": "gemini-3.8-flash" }`

### Calling it from the frontend later
```js
const form = new FormData();
form.append('audio', blob, 'recording.webm'); // blob from MediaRecorder
const res = await fetch('http://localhost:3001/api/transcribe', { method: 'POST', body: form });
const { transcript, fillerWords, wordCount } = await res.json();
```

## Key decisions

- **Gemini audio instead of the browser's Web Speech API.** Browser speech recognition usually drops "um"/"uh" and only works in Chrome/Edge. Filler-word counting is a core PitchPerfect metric, so we prompt Gemini to transcribe verbatim.
- **Backend server, not browser calls.** The API key stays on the server and is never sent to users' browsers.
- **Structured JSON output.** Gemini returns a fixed schema (`transcript` + `fillerWords`), so the frontend never has to parse free text.
- **Model set in `.env`.** Change `GEMINI_MODEL` without touching code.

## Problems we hit (and fixes)

| Problem | Fix |
|---|---|
| `node: command not found` | Node wasn't installed. Installed with Homebrew |
| `.env` was empty (0 bytes) | The file wasn't saved after pasting. Saved with Cmd+S |
| 404 "gemini-2.5-flash is no longer available to new users" | Switched the model to `gemini-3.8-flash` |
| 503 "model experiencing high demand" | Temporary on Google's side. Added automatic retries with backoff |
| 403 "Gemini API has not been used in project…" | Enabled the Gemini API in Google Cloud for the key's project |
| 403 "caller does not have permission" (once, right after enabling) | Went away on retry, most likely because the change was still taking effect |

## Test results

Tested with a clip generated by the Mac `say` command:
> "Um, so, like, I worked on a project last summer where, uh, we built a website for a local nonprofit. And, you know, it was basically my first time leading a team."

- Transcript came back **word for word**.
- All **6 filler words** were detected: um, so, like, uh, you know, basically.
- Took about **14 seconds** once the API was fully enabled. The first successful run took 112 seconds because of busy-server retries.
- Not yet tested with a real human voice recording, which will have more natural "um"s and pauses.
